# How To: Authenticate with the Task Management API

> Generated by docpilot from source: `task-management-api/auth.py`, `routers/tasks.py`

All task endpoints require a valid JWT access token. This guide explains how to obtain a token and include it in your requests.

---

## Step 1: Obtain a JWT Token

Send a `POST` request to `/auth/token` with your credentials as form data (not JSON).

**curl:**
```bash
curl -X POST http://localhost:8000/auth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=alice&password=secret123"
```

**Python (httpx):**
```python
import httpx

response = httpx.post(
    "http://localhost:8000/auth/token",
    data={"username": "alice", "password": "secret123"},
)
token_data = response.json()
access_token = token_data["access_token"]
```

**Successful Response `200 OK`:**
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJhbGljZSIsImV4cCI6MTc0ODc2ODAwMH0.abc123",
  "token_type": "bearer"
}
```

**Failed Response `401 Unauthorized`:**
```json
{
  "detail": "Incorrect username or password"
}
```

> **Note:** The request body must be `application/x-www-form-urlencoded` (standard OAuth2 password flow), not `application/json`. Sending JSON will result in a `422 Unprocessable Entity` error.

---

## Step 2: Include the Token in Subsequent Requests

Add the token to the `Authorization` header of every request to a protected endpoint. The format is:

```
Authorization: Bearer <your_access_token>
```

**curl example — list tasks:**
```bash
curl http://localhost:8000/tasks \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**Python (httpx) example — create a task:**
```python
import httpx

headers = {"Authorization": f"Bearer {access_token}"}

response = httpx.post(
    "http://localhost:8000/tasks",
    headers=headers,
    json={"title": "Write tests", "status": "pending"},
)
print(response.json())
```

## Step 3: Handle Token Expiry

Tokens expire after a fixed duration. When a token has expired, the API returns:

```json
{
  "detail": "Could not validate credentials"
}
```

When you receive this response (`401 Unauthorized`), re-authenticate by repeating Step 1 to obtain a fresh token.

## Using the Swagger UI

FastAPI's built-in Swagger UI at `http://localhost:8000/docs` supports the OAuth2 password flow directly:

1. Open `http://localhost:8000/docs` in a browser
2. Click the **Authorize** button (lock icon, top right)
3. Enter `username` and `password` in the form
4. Click **Authorize** — Swagger will store the token and include it automatically in all "Try it out" requests

## How Authentication Works Internally

The `get_current_user` dependency in `auth.py` is the core of the authentication system:

```
Request with Authorization: Bearer <token>
        │
        ▼
  auth.py: get_current_user()
        │
        ├── Extract token from Authorization header
        ├── Decode JWT with python-jose (verify signature + expiry)
        ├── Read "sub" claim → username
        ├── Query DB for User with that username
        └── Return User object (or raise 401 if any step fails)
        │
        ▼
  Route handler receives: current_user: User
```

The `SECRET_KEY` used to sign tokens is read from the application config. Tokens are signed with the `HS256` algorithm.
