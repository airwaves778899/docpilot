# Task Management API — Glossary

> Last updated: 2026-06-01
> Generated by docpilot from source: `task-management-api/`

| Term | Definition |
|------|------------|
| Task | The core domain entity. Represents a unit of work owned by a user. Stored in the `tasks` table. Has a status lifecycle: `pending` → `in_progress` → `done` or `cancelled`. |
| TaskStatus | An enum with four values: `pending` (newly created, default), `in_progress` (actively worked on), `done` (completed), `cancelled` (abandoned). Stored as a string column in SQLite. |
| JWT | JSON Web Token. A signed, self-contained token used to authenticate API requests. Issued by `POST /auth/token` and must be included in the `Authorization` header of all protected endpoints. |
| Bearer token | The HTTP authentication scheme used by this API. Format: `Authorization: Bearer <jwt_token>`. All task endpoints require a valid Bearer token. |
| Pydantic model | A Python class used for request/response validation and serialization. Defined in `schemas.py`. Separate schemas exist for creation (`TaskCreate`), updates (`TaskUpdate`), and API responses (`TaskResponse`). |
| ORM session | A SQLAlchemy `Session` object that manages database transactions. Injected into route handlers via FastAPI's dependency injection system (`Depends(get_db)`). Each request gets its own session, closed after the request completes. |
| owner_id | The `id` of the `User` who created the task. Set automatically from the JWT claims when a task is created. Users can only read and modify their own tasks. |
| dependency injection | FastAPI's `Depends()` mechanism used to provide the DB session and the current authenticated user to route handlers without repeating boilerplate. |
| create_all | `Base.metadata.create_all(bind=engine)` — called at application startup in `database.py` to create SQLite tables if they do not exist. Safe to call repeatedly (no-op if tables already exist). |
